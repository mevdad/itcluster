# Реестр изображений IMG-01 — IMG-18

Файл генерируется командой `npm run images` (`tools/images/generate.py`). Не редактируйте вручную.

Реальных фотографий компании в исходных материалах нет, поэтому все кадры — собственные иллюстрации и визуализации. Они **не** изображают дата-центры, сотрудников или проекты компании. Реальные фотографии подключаются поверх этого реестра, без правки генератора (см. ниже).

## Быстрый путь: `npm run photos` (оптимизация в WebP)

Подходит и для своих фото, и для стоковых (Pexels). Оригиналы любого размера кладутся в `photos/src/`, слот и описание — в `photos/photos.json`:

```json
{ "img-02": { "file": "server.jpg", "alt": "Что на фото", "status": "стоковое фото", "objectPosition": "50% 40%",
             "credit": { "author": "Имя автора", "url": "https://www.pexels.com/photo/…", "title": "Название", "license": "Pexels License" } } }
```

`npm run photos` обрезает каждое фото точно под пропорции слота (рабочее поле — `objectPosition`), сжимает в WebP (десктоп по размеру слота: 1000 px для карточек, до 1600 px для крупных кадров; телефон до 800 px; бюджет ~220 и ~110 КБ), пишет файлы в `public/images/photos/`, подключает их через `src/content/image-overrides.generated.ts` и обновляет `docs/PHOTO-CREDITS.md`. Статус: `реальная фотография` (подписи не нужны) или `стоковое фото` (на картинке и в подписи галереи появляется «Иллюстративное фото», кадр не выдаётся за площадку компании).

## Как заменить картинку вручную

1. Положите файл в `public/images/real/` (JPG или WebP, около 2000 px по длинной стороне, до ~400 КБ). Для телефона можно положить отдельный кадр, например `…-m.jpg`.
2. Найдите код слота в таблице ниже (например, IMG-06 → id `img-06`).
3. Добавьте запись в `src/content/image-overrides.ts`:

   ```ts
   "img-06": {
     desktop: { src: "/images/real/rack-msk.jpg", width: 2400, height: 1600 },
     mobile: { src: "/images/real/rack-msk-m.jpg", width: 1200, height: 900 }, // необязательно
     alt: "Что именно на фото",
     status: "реальная фотография",
     objectPosition: "50% 40%", // необязательно: какая часть кадра остаётся видна при обрезке
   },
   ```

4. `npm run typecheck` — опечатка в id, пропущенный `alt` или неверный статус не скомпилируются.

Что происходит автоматически:

- пропорции блока на странице остаются от слота (колонки «Десктоп» и «Телефон» ниже), фото любого размера вписывается в него с `object-fit: cover`; положение кадра задаёт `objectPosition`;
- подписи на картинках («Иллюстрация», «Визуализация», «Иллюстративное фото»), пометки под галереей инфраструктуры и «Схема, не карта» сейчас выключены одним переключателем `showImageLabels` в `src/content/site.ts` (с 23.10.2026 по решению владельца). `true` вернёт все сразу; для реальной фотографии подпись не показывается и тогда;
- `width`/`height` указывайте реальные размеры файла: они нужны браузеру, на раскладку не влияют.

Проверьте вручную: подпись к кадру (если есть) описывает именно ваше фото; на фото нет лиц или данных клиентов без согласия; первый экран (IMG-01) после замены остаётся лёгким, так как влияет на LCP.
